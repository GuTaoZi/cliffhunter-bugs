== condition (c): invariance -- is the cliff a property of the CONSTANT?
================================================================================================
  dataset       matches  knob that trips it  cliff (docs)  cliff (latency)
  docs              101              <= 101         58.9x            52.1x
  docs_k1000      1,000            <= 1,000         57.8x            45.7x
  docs_mirror       101              <= 101         58.9x            54.8x

  Read this table as: the knob does not set the SIZE of the cliff, it sets how many
  matching documents a workload needs in order to fall off it. Raising the constant
  10x left the cliff the same depth and simply moved which workload trips it.
  The rule is: a workload falls off the cliff whenever
      (number of matching documents) <= internalQueryPlanEvaluationMaxResults
  and the matches are positioned early in the bad plan's index order. Since the
  match count is a property of the DATA and the knob is a server constant, no
  setting of the knob excludes the bad regime -- which is condition (c).
